# Narva 学校与足球场展示环境

## 当前结果

车辆查看器使用 SiguaResearch 最新已接受的地图交付 v20 中的 FixedDisplay：简化查询几何着色、固定精度、无距离 LOD。选区来自 SiguaWiki 的学校/足球场场景记录，保留学校、两组看台、两个球门及全部 79 个摆放实例。两个数据集的 prototype 编号不同，按准确的源 meshPath 对接。

足球场中心为源坐标 `[135, -515, 2.0703125]` 米。场景在这里对齐车辆查看器原有的载具中心与地面基准，不改变车辆模型、武器站、乘员或相机的局部绑定。地形保留学校台阶高差和 101 × 131 网格，源高度已包含 Landscape 平移，不能再次叠加。

真实操作弹体另行接入学校源查询几何与预建 BVH，不用 FixedDisplay 计算命中。发射时沿用 Wiki 的弹体算法、球形碰撞半径及 `traceComplexOnMove` 配置，通过连续扫掠在首次表面接触处截止；穿透后效是有限的分析线，不会让已销毁的物理弹体继续飞行。

每次实际发生碰撞后只保留最近一次命中的参考线和标记：绿色表示材料计算通过，红色表示停止，黄色表示证据不足。非爆炸弹的后效复用已有穿透算法，并接入本次反编译确认的正反向简单/复杂查询合并规则；反向出口不重复扣算一层装甲。当前学校建筑的原生命中法线、每组件命中数量和部分组件类别仍未核实，因此这些表面显示“穿透未确认”，不以导出三角面交点数冒充游戏中的层数，也不取法线绝对值强行得出可穿透结论。

该接入不包含建筑血量/摧毁、爆炸径向伤害、实时导弹制导遮蔽或动态场景；不能据此宣布所有建筑的战斗防护能力已验证。碰撞正反面采纳仍在原生查询边界内，当前几何接触演示不等于完整 Engine 查询对等。HE/TOW 等仍在命中处截止，但爆炸后效只给出未模拟提示。

## 来源与发布边界

- 来源任务：`codex://threads/01a04644-34eb-7b60-a30a-037002823e68`。
- 研究基线：SiguaResearch `origin/trunk` 已接受的 map delivery v20；v20 是无损分发优化，本次没有重新提取或修改研究资产。
- 产品只持有展示代码，共享数据和解码器仍归 SiguaWiki。不要把地图 payload 复制进 Armor Git 或部署包。
- 当前公共 Wiki 尚未发布 `/data/maps/narva/fixed-display.json` 和 `/algorithms/maps/fixed-display-format.js`，已实测 HTTP 404。因此本轮只完成本地预览，不能直接发布这个构建。上线前须先按地图资源自己的发布权限与流程将同一版本的场景、地形、FixedDisplay 及解码器发布到 Wiki，并重新验证产品默认源。
- 本地适配器仅监听 `127.0.0.1`，只提供具名 FixedDisplay、学校场景/地形，以及 Wiki 已有学校查询几何/BVH；不公开私有地图服务或任意 custody 文件。

## 本地复现（PowerShell 7）

在产品 checkout 中启动资源适配器；它只读取已有资产，不生成新快照：

```powershell
node tools/dev/serve-narva-school.mjs --display-root D:/Dev/SiguaResearch/.local/windows-localappdata-custody/map-materialized/narva-delivery-v20 --wiki-root D:/Dev/SiguaWiki --port 4191
```

在另一个终端构建并启动预览：

```powershell
$env:NEXT_PUBLIC_SIGUA_MAP_ORIGIN = 'http://127.0.0.1:4191'
npm run build
node tools/dev/serve-product-preview.mjs
```

预览地址：<http://127.0.0.1:4188/squad/vehicles/adf--m1a1--mbt?a=adf-ausm1a1>。

预览服务器复用 Vinext 生产服务，并在回环地址补齐 Windows 静态文件路径及线上 `/squad` 前缀行为，不修改依赖。外层端口默认 4188、SSR 端口为其下一端口。重新构建前应停止自己的预览进程，避免在运行中的生产目录上混用新旧构建。正常线上构建不能带上述回环资源地址。

## 成本与验证

- 只请求学校范围的 24 个几何资源及地形；其未压缩二进制总量为 402,519 字节（约 393 KiB）。这不含两个描述 JSON 与共享解码器；本地压缩传输实测三者合计 281,029 字节。
- 79 个摆放实例按共享几何实例化，与地形合计 25 次环境绘制、71,493 个三角形。不重复下载纹理，不附加旧 LOD/GLB，不每帧生成几何；解析结果在页面内跨载具复用。
- 碰撞层另取学校已有的查询几何与 BVH，未压缩二进制合计 1,980,816 字节，跨载具缓存；79 个实例加地形共 80 个查询对象，仅用于 CPU，不增加环境绘制。最新命中线使用固定容量缓冲区，不累积所有射击记录。
- 回归覆盖源 meshPath 配对、足球场完整性、源坐标/非均匀缩放、地形高差与三角绕序、实例化、原数据不被修改、资源服务边界、环境与车辆命中/适配根节点分离。
- 本地生产构建已在 Edge 验证外观/俯视、炮手与驾驶员实景，确认载具位于足球场中央，浏览器无错误。当前机器炮手视角 90 帧采样中位帧间隔约 6.3 ms，仅为该机器的静止视角观测，不代表低端设备或持续旋转的性能结论。
- 缺少查询回调的回归已复现并修复：1 cm 球体高速射向 10 m 薄墙，修复前查询 0 次并飞到 1000 m；修复后查询 1 次，在球心 9.99 m 截止。Edge 真实操作已验证草地和混凝土看台接触；看台穿透保持黄色未确认，而不是报告通过或失败。
- 9 月 5 日收尾构建通过 14 项数据、434 项查看器和 34 项工具测试、类型检查与生产构建；lint 只有两处既有图片警告。最终 Edge 刷新与主炮射击没有站点错误，仅观察到浏览器扩展自身的 `Failed to fetch`，不将其误报为站点资源失败。
- 当前机器对实际 AP/机枪配置执行各 100 次完整弹道计算，命中及 12 秒无命中控制的 p95 均低于 1.1 ms；不等于浏览器渲染或低端设备性能保证。回归另覆盖薄面、边角、非均匀变换、BVH 面索引、材质三态、严格阈值、吸收顺序、有限末端，以及最近命中保留/替换/释放。
- 另一个 UI 问题：从炮手退出再切到驾驶员时，驾驶员视角仍显示上个武器的弹药 HUD，并出现“当前 equipment 尚未进入可发射 runtime selector”提示。地图本身正常加载；该武器状态展示问题未混入本次地图替换，需单独修复。

本轮门禁：`npm run check`、`npm run lint`、`npm run build`、`git diff --check`，以及实际 Edge 操作与控制台检查。此前地图接入执行过部署打包检查，但打包验证不等于发布；本轮没有部署。
